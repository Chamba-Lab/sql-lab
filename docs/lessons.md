## Lab 1.1
- **The `python -m sqlite3` console differs by Python version.** `.help` prints a command list only in 3.15 (3.12–3.14: "Enter SQL code and press enter."). An unknown dot command such as `.tables` errors in 3.13+ but in 3.12 is buffered as SQL until a `;`. Quote both when a lab touches it, and read `Lib/sqlite3/__main__.py` of each version instead of guessing.
- **Piping input into the console from PowerShell 5.1 breaks the first line** (the first command was not recognized as `.help`); piping from Bash did not. Drive console sessions from Bash, or start them with a harmless SQL line, when verifying.
- **Opening a misspelled file silently creates a 0-byte database**, in every version measured (3.12, 3.15, SQLite 3.45.3). It is the most likely "my data is gone" report from learners: first ask for `pwd` and the file size.
- **On Windows a database file open in a console cannot be deleted or rebuilt** (`PermissionError: [WinError 32]`, message in the Windows locale). Cleanup steps say `.quit` first.
- **With Python 3.12, output to a pipe uses cp1252 on Windows**, so accents come out garbled when the console's output is captured (3.15 defaults to UTF-8). In a PowerShell window they display correctly. Tests that run the console set `PYTHONIOENCODING=utf-8`.
- **Error messages of the console changed inside the supported range, and the CI matrix missed it.** `.tables` prints `Error: unknown command or invalid arguments:  "tables".` in 3.13 and 3.14 and `Error: unknown command: "tables"` in 3.15; the guide quoted only the 3.15 text because it was checked on the CI versions (3.12, 3.15). Quote only the stable start of a version-dependent message, and run every quoted message on every Python at hand (`uv python list --only-installed`), not only the CI ones.
- **The console banner has four lines and depends on the OS.** All of 3.12 to 3.15 print `Each command will be run using execute() on the cursor.` and `Type ".help" for more information; type ".quit" or CTRL-Z to quit.` (CTRL-D outside Windows, from `eofkey` in `__main__.py`), while `.help` in 3.15 always says CTRL-D. A learner who reads words the guide does not mention (`execute()`, cursor) stops to ask: quote the whole banner and gloss each line, even with "you do not need this yet".
- **Plain `ls` in Bash shows names only.** A step that depends on a file size gives `ls` for PowerShell (the `Length` column) and `ls -l` for Bash (the number before the date). `jobs.db` is 12288 bytes and the misspelled file 0 bytes on every Python measured (3.12.16, 3.13.14, 3.14.4, 3.15.2, Anaconda 3.12.7).
- **A fresh venv prints `[notice] A new release of pip is available`** after `pip install` (seen with the Microsoft Store Python 3.13.14: pip 26.1.2 → 26.3). Learners do not know whether to act on it; `SETUP.md` says it can be ignored.
- **"Planilla" means payroll in Peru.** Neutral Spanish for a spreadsheet is "hoja de cálculo".
- **In Git Bash on a machine with Anaconda, activating the venv left Anaconda's Python in charge** (3.12.7, SQLite 3.45.3), exactly as `SETUP.md` warns. Verify with `sys.prefix` every time.

## Lab 1.2
- **pytest output garbles accents in a pipe on Python 3.12 to 3.14 (Windows).** Output to a pipe or a file is written in cp1252 (`devolvi� ning�n`); 3.15 writes UTF-8. A real PowerShell console window showed accents correctly either way (read back from the console buffer), and Git Bash 2.48's mintty gave Python a console too (`isatty()` True, UTF-8). The harness calls `sys.__stdout__.reconfigure(encoding="utf-8")` in `conftest.py`, so the output is the same everywhere, including agents, CI logs and `> out.txt`.
- **What `Connection.execute()` does with a learner's file, the same in 3.12 to 3.15:** a file with only a comment (or empty) returns `description = None` and no rows, so a `-- TODO` starter fails on the comparison, not on a syntax error; a comment before or after the statement is fine; two statements raise `ProgrammingError: You can only execute one statement at a time.`
- **Call `pytest.fail` outside the `except` block.** Inside it, pytest prints the original exception and "During handling of the above exception, another exception occurred" above the learner-facing message.
- **SQLite accepts things the standard does not**, measured in SQLite 3.45.3, 3.50.4 and 3.53.1: a misspelled name in double quotes (`"nmae"`) becomes the text `'nmae'`; an alias in single quotes (`AS 'profit'`) works; an alias works in `WHERE`. An alias in another column of the same `SELECT` fails (`no such column`), as in the standard.
- **`price * 1.18` shows floating-point noise on some rows only** (5.0, 9.5 and 11.0 give `5.8999999999999995`, `11.209999999999999`, `12.979999999999999`), and `ROUND(x, 2)` returned values equal to the Python literals (`5.9`, `11.21`) in every build measured. Exact float comparison in the tests is safe once the task asks to round.
- **A missing comma is silently an alias** (`SELECT name price` returns one column `price` holding names): the column check of the harness turns it into a readable failure. It is the strongest trap of lab 1.2.
- **Concept examples can spoil a later prediction with their own output.** `1200 * 3.7413` prints `4489.5599999999995`; the `ROUND` example shows only the rounded column. Run every example and read its raw output before choosing what to show.
- **`python -m pytest -k task1` matches `TestTask1Menu`**: `-k` ignores case, so lowercase task selectors work with the class names.
- **Test data that cannot tell two roundings apart lets the wrong one pass** (found by the validator after the lab was built). With every price a multiple of 0.5, `price * 1.18` never had a third decimal, so `ROUND(…, 3)` and `ROUND(…, 4)` passed task 3 while the README promised "a lo más tres" decimals. Changing the alfajor to 3.7 (3.7 × 1.18 = 4.366) makes both fail, and `ROUND(x)`, `ROUND(x, 1)` and no rounding still fail, in 3.12.16, 3.13.14, 3.13.18, 3.14.4, 3.15.2 and Anaconda 3.12.7. For every rounding a test checks, run `ROUND(x, n − 1)`, `ROUND(x, n + 1)`, `ROUND(x)` and no rounding as mutations, and pick data where each one changes at least one row.
- **Stock PowerShell 5.1 writes `>` in UTF-16 with a byte-order mark** (bytes `FF FE`, measured with `powershell -NoProfile`, 5.1.26100). The first harness read the files with `read_text(encoding="utf-8")` and crashed with a `UnicodeDecodeError` traceback; a UTF-8 BOM (VS Code, some editors) was harmless. The agent's own PowerShell had `$PSDefaultParameterValues['Out-File:Encoding'] = 'utf8'`, which hid it: check encodings in a shell started with `-NoProfile`. The harness now reads UTF-8 with or without BOM and UTF-16, and explains in Spanish any other encoding (a cp1252 file with accents).
- **A learner who keeps the prediction's query and writes the task's below it gets `ProgrammingError: You can only execute one statement at a time.`**, in English. The harness now says, in Spanish, that the file has more than one query, and the task steps say "Reemplaza", not "Escribe".
- **Learners do not know what `near "AS": syntax error` means** (the learner put `AS` inside `ROUND(…)`). The README now explains `near "X"` (look just before `X`) and `no such column`, measured the same in SQLite 3.45.3, 3.50.4 and 3.53.1.
- **A flag that only the command dissection shows is not taught.** `-k` and `-v` were in the dissection and in the syllabus notes as taught, but no task used them; tasks 2 to 4 now run `python -m pytest -k taskN` and task 4 runs `-v`.
